# 任务进度与续接

任务状态存于开发项目的 `.scratch/matt-mainflow/<task-slug>/state.md`，每个任务一份。规格和工单沿用项目已配置的路径或外部系统；状态文件只存链接、决策摘要和证据，不复制正文。

创建前检查同名任务，使用未占用的简短 slug；不要覆盖旧任务。项目以仓库标识或项目名称记录，产物路径相对项目根目录，避免依赖某台机器的目录布局。写入前重新读取文件，保留已有记录及他人更新；存在冲突时先核对，不用旧副本覆盖新状态。

```markdown
# <任务名称>

- 项目：<仓库标识或项目名称>
- 目标：<一句话目标>
- 当前阶段：<1–6 或初始化>
- 状态：<进行中 / 待确认 / 暂停 / 阻塞 / 已完成>
- 下一步：<具体动作；等待哪项决定>
- 恢复位置：<正在处理的工单、未完成动作；无则省略>
- 更新时间：<实际本地时间及偏移>

## 阶段

| 阶段 | 状态 | 产物或证据 | 用户确认 |
|---|---|---|---|
| 1 需求讨论 | 未开始 | | |
| 2 写规格 | 未开始 | | |
| 3 拆工单 | 未开始 | | |
| 4 实现 | 未开始 | | |
| 5 代码审查 | 未开始 | | |

## 执行范围

- 分支和起始 HEAD：
- 起始已有改动：
- 本任务工单及状态：
- 本任务文件、提交和差异范围：

## 验证

- <检查内容、实际命令或操作、结果、对应代码版本或差异、证据位置>
- 未验证：<缺失验收及原因>

## 决策与转换历史

- <实际时间>：<用户决定、阶段转换或范围变化，简短记录依据>
```

阶段状态可用：未开始、进行中、待确认、已确认、已跳过、需复核。已跳过必须记录用户同意及已有替代证据；尚未执行的测试填未验证，不填通过。完成状态以产物、实际验证和用户确认共同判断，不以阶段数字判断。

阶段产物完成、用户确认、暂停、失败阻塞及范围变化时更新状态。普通工具调用不逐条记流水账。用户确认只记录本次确实出现的决定，不补造历史确认或时间。

## 回退与变更

- 需求变化：规格、工单、实现、审查、复盘逐项判断影响，受影响项标“需复核”。
- 规格变化：从工单向后判断影响；与变化无关的已有工作保留有效。
- 工单变化：核对实现范围、依赖及审查覆盖。
- 代码变化：对应测试和审查结果需核对是否仍适用。
- 返回某阶段仅表示重新进入该阶段；不删除旧产物、撤销代码或改写外部工单。

续接时检查实际项目、分支和产物是否仍匹配。记录丢失时根据现有产物提出恢复方案，获得用户确认后重建；不假装记得不存在的阶段决定。目录中不存凭据、私人会话原文或无关资料。
