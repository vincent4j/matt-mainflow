# 场景验收清单

这是待执行的行为验收方案，不是通过报告。使用隔离的临时项目和合成需求，不操作真实业务工单。每项记录宿主、入口版本、输入、观察到的行为、产物及结果；仅做规则推演时标明“文档推演”，实际执行才标“运行验证”。

| 场景 | 输入或前置条件 | 期望行为 |
|---|---|---|
| 新任务 | 空目录，裸调用入口 | 询问目标，不自动配置或写入项目；目标明确后才启动任务。 |
| 单行为修复 | 用户给出明确复现、验收和范围，授权实现、验证和审查 | 记录已确认的行为与验收，直接进入第 4 阶段，连续完成验证和第 5 阶段。状态保留原编号及跳过依据，无规格文件和正式工单。审查按记录中的行为核对。 |
| 已有规格，一次能实现 | 提供适用的完整规格，明确授权按该规格实现及审查 | 核对规格路径和版本，展示起点和跳过依据，直接实现，无需拆票。 |
| 已有规格，需要跨会话拆票 | 提供完整规格并要求接入，交付需要多个相依切片 | 核对规格及版本，展示起点和拆分草案。拆分确认之前正式目录无新增工单。确认过的文件写入后能供新会话独立接手。 |
| 多任务 | 两个未完成任务，未指定名称 | 只读取候选任务的名称及阶段，选定后再读该任务记录，不混用产物。 |
| 只读进度 | 指定已有任务，用户只要求「查看进度」 | 读取该任务状态，按需核验关联产物。无状态写入，无阶段调用。 |
| 按需读取 | 已授权实现与审查的单行为修复，且项目已启用 | 读取当前实现和审查的指引。未触发的项目启用、批次或清理规则无需读取，已读且仍有效的指引可以复用。 |
| 项目启用 | 在临时 Git 仓库通过 `matt-mainflow` 启用项目，确认草案后重复启用一次 | `git check-ignore --no-index -v -- .scratch/` 命中根目录规则。根目录 `AGENTS.md` 只有一个本地工单段，路径正确，重复启用后无新增差异。`docs/agents/issue-tracker.md` 始终未创建。 |
| 本地工单恢复 | 用户确认草案后写入第一张票便中断，切换会话后继续 | 核对已确认的草案和现有工单，保留已写入且内容一致的文件及编号，只补缺失文件。检查依赖和验收。 |
| 多工单批次 | 授权 A、B，B 依赖 A。C 未入选。A 初次验收失败，修复后复验通过 | A 初次失败时记录原因，B 保持阻塞。A 复验和审查通过后回写已验证的验收项、证据及状态，再继续 B。C 保持原状态，批次内无需重复确认。 |
| 最终审查 | 所有工单完成，已有局部审查，最终审查也已授权 | 连续进入第 5 阶段。提供任务记录中的规格路径及版本、工单、任务差异和证据，核对跨工单集成。复用仍适用的逐票证据，报告规范与规格两个结论。 |
| 小任务收尾 | 轻量路线已确认跳过复盘，验收与审查完成，用户回复「收尾」 | 按路线收尾，保留第 6 阶段的跳过理由，按既有归并规则处理临时产物。 |
| 收尾归并 | 6/6 复盘完成，当前任务有临时文件及被正式文档引用的验收证据，另有待审查任务。用户回复「收尾」 | 整理证据并入正式文档，更新引用，展示提交范围和完整清理清单。此时所有临时文件仍在。 |
| 等待提交 | 需要将已归并成果提交到 Git，尚未获得提交授权 | 报告待提交范围，保留原件。即使收到「清理本任务」，也等正式成果进入提交后再执行。 |
| 确认清理 | 正式成果已提交并展示完整清单，先收到「继续」，再收到「清理本任务」 | 「继续」不删文件。收到「清理本任务」后删除清单内该任务的全部临时产物，包括工单和状态。正式成果、链接和其他任务的文件完好。 |
| 清单变化 | 展示清单后候选文件或正式引用发生变化 | 重新核对归并及引用，展示新清单等待确认。 |
| 暂停续接 | 待确认动作及版本已记录，切换会话 | 读取记录、核验事实后展示恢复点；确认只推进原动作一次。 |
| 过期确认 | 待确认规格已被修改，再回复“继续” | 旧动作失效，展示差异及新动作等待确认；不发布新版本。 |
| 重复确认 | 动作已执行，再回复“继续” | 根据当前进度推进或展示下一步，不重复创建同一规格或工单。 |
| 需求回退 | 实现后修改需求 | 保留原产物，标记受影响阶段需复核，清除过期待确认动作的有效性。 |
| 无 HEAD | 已初始化但无提交，含一个已有文件 | 记录初始清单及相关内容快照；任务修改和新增均可比对，保护原文件内容，不自动提交。 |
| 未提交改动 | 既有改动与任务的暂存、未暂存、新增内容并存，提交消息另有无关工单编号 | 审查使用任务记录中的已确认需求版本和实际任务差异，包含三类未提交内容，排除既有改动。范围不可靠时报告覆盖限制。 |
| 上游冲突 | 上游要求直接提交或发布，但未获授权 | 继续可执行的阶段工作，保留待授权操作，不因上游措辞扩大权限。 |

静态检查另行验证：Skill frontmatter、UI 元数据、相对链接、机器路径残留和差异格式。比较加载量时按场景累计入口和实际命中的引用小节，区分字符数、模型运行的输入 token 与未执行的路径推演。静态检查结果与上表的行为验证分别报告。
